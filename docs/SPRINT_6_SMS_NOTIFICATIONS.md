# Sprint 6 — SMS Notifications

Status: implemented.

## Delivered workflows

- Administrator workspace for queuing and monitoring guardian SMS notifications
- Recipient eligibility based on an active student link, recorded SMS consent, and a verified mobile number
- General, attendance, meeting, and home-visit message categories
- Unique event keys that prevent duplicate notifications for the same business event
- Masked recipient numbers in API responses, the interface, and retained SMS history
- Provider-independent send service with queued, sending, sent, delivered, failed, and cancelled states
- Retry tracking, retained provider errors, configurable retry limits, and a queue-processing management command
- Audit events for administrator queue and send actions
- Optional automatic notification queueing for unexcused absences
- Automatic cancellation of an unsent attendance alert when the attendance record is corrected

## Safety and policy rules

- Only Administrators can view, queue, send, or retry SMS notifications in Sprint 6.
- A guardian must be linked to the student, have SMS consent recorded, and have a verified mobile number.
- Full recipient numbers are sent only to the provider boundary; application responses and logs use a masked value.
- An event key is globally unique. Repeating it returns a conflict and does not create a second message.
- Sensitive risk labels are not generated by this sprint. Any such wording must come from a future reviewed risk/intervention workflow.
- Meeting and home-visit messages are manually reviewed by an Administrator and should state the purpose, exact schedule, and school contact details.
- Attendance automation is disabled by default because the school notification threshold is still a policy decision.

## Provider configuration

The default `ConsoleSMSProvider` is a safe local adapter. It records a simulated provider acceptance and does **not** contact a real mobile number. Configure `SMS_PROVIDER_CLASS` with a production adapter before deployment.

```env
SMS_PROVIDER_CLASS=notifications.providers.ConsoleSMSProvider
SMS_MAX_RETRIES=3
SMS_AUTO_ATTENDANCE_NOTIFICATIONS=False
```

To process queued and retryable failed notifications outside the interface:

```cmd
.venv\Scripts\python.exe manage.py process_sms_queue --limit 100
```

In production this command should be invoked by the approved background worker or scheduler. The retry service is synchronous in Sprint 6 so the domain workflow can be verified before Celery/Redis is introduced with the production SMS provider.

## Deferred deployment decisions

- Approved attendance notification threshold and sending hours
- School-approved message templates, contact details, privacy wording, and language variants
